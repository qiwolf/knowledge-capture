# 公开发布说明

公开项目名称为 `knowledge-capture`，GitHub 所有者为 `qiwolf`，Alpha 版本为 `0.2.0-alpha.1`。目标容器镜像为 `albatrosswang/knowledge-capture:0.2.0-alpha.1`。本项目采用 MIT 许可，版本对应的源码、演示和双架构镜像由发布流程核验。

## 发布内容

采用明确白名单组织公开目录：

- `knowledge_capture/`：应用源码和工作台静态资源，排除缓存文件。
- `extension/`：浏览器插件源码、测试和说明，排除运行缓存及依赖目录。
- `tests/`：使用隔离临时目录的测试，不包含真实知识库。
- `README.md`、`pyproject.toml`、`requirements.lock.txt`、`.gitignore`、`.dockerignore`、`.env.example`。
- `LICENSE`、`Dockerfile`、`compose.yaml`。
- `providers.example.json` 与脱敏后的 `providers.machine-room.example.json`；后者仅为服务合约示例，地址使用 example.org 占位。
- `docs/evaluation/`：仅两份公开短例与固定向量评估，不包含实际业务原文或服务地址。
- 审阅后的 `docs/media/demo.mp4` 与 `docs/media/poster.png` 与 `docs/media/demo-preview.gif`：独立演示库截图制作，使用虚构资料。
- `docs/知识维护API.md`、`docs/容器部署与发布.md`、`docs/检索与分类评估.md`、`docs/验收与限制.md`、本文。

历史项目记录含个人工作环境、验证样本与部署信息，不作为公共使用文档发布。不要将整个工作目录直接压缩上传。

## 必须排除

真实数据目录、同步参考资料、导出件、模型原始响应、截图及验收产物、私有配置、令牌、`.env`、`*.local.json`、虚拟环境、缓存、构建产物、旧 `.git` 历史与个人 `AGENTS.md` 均不得进入公开包。

历史 `docs/` 目录只按上面的白名单取文件。即使记录没有原始密钥，机器地址、个人绝对路径、凭据别名和资产清单也不应公开。

`.gitignore` 只能防止未跟踪文件被误加入，不能从已提交文件或历史中移除内容。公开发布应从经过核对的干净目录建立版本记录；提交前核对待提交文件清单和实际内容。

## 发布前检查

在隔离数据目录运行 Python 与插件测试。随后构建容器，验证健康状态、认证拒绝、知识新增与历史读取、重启后的数据与令牌保留、停止行为。使用至少一份实际公开中文资料检查从采集到正文阅读的链路。

可选模型、读取、搜索、语义和重排服务须分别报告已测试与未测试状态。Laya 未正式集成时保留“待实验”表述；不要因文档提到某工具就声称支持。

公开内容中保留用于网络访问限制测试的通用私网示例地址与网段；这些测试值不是部署地址。发布时仍应检查是否混入真实主机地址、个人目录、凭据和业务资料。

## 发布与升级

外部创建仓库、推送源码、发布版本或推送镜像应针对已审阅的内容执行。项目文档不预设这些操作已获批准或已经完成。发布说明应记录具体提交、测试结果、镜像标识和已知限制，避免只写“构建成功”。

升级与备份操作见 [容器部署与发布](容器部署与发布.md)。在没有独立恢复验证前，不应将生成的 ZIP 或存在的数据卷视为已经验证的备份。
