# 容器部署与发布

本方案将应用和依赖封装为容器，知识数据单独持久保存。工作台、Bearer 认证、采集队列和定时任务随服务启动。公开镜像支持 Linux AMD64 和 ARM64；外部服务仍需用户配置并验收。

## 一次启动

安装并启动 Docker Desktop 或支持 Compose 的 Docker Engine，在项目目录执行：

```sh
docker compose pull
docker compose up -d --no-build
```

需要从源码构建时执行 `docker compose up -d --build`。

随后打开 `http://127.0.0.1:8765`。默认端口只映射宿主机的本机回环地址。首次打开工作台时，将以下命令显示的私有令牌粘贴到工作台的令牌输入框：

```sh
docker compose exec knowledge cat /data/.api-token
```

令牌由应用生成，以 0600 权限保存在数据卷中。容器重建后沿用原令牌。不要将令牌粘贴到聊天、报告或共享文档。模型、正文读取服务等配置在工作台中设置；未配置服务不会被假定为已接入。

```sh
docker compose ps
docker compose logs --tail=50 knowledge
```

`healthy` 表示本机网关能回答健康请求。它不证明外部模型、公众号、视频服务或语义检索已经通过业务验收。

## 数据、安全与停止

Compose 创建 `knowledge-data` 命名卷，保存原文、历史、维护笔记、索引、配置与令牌。容器以 UID/GID 10001 非 root 运行；应用文件系统只读，临时文件使用 `/tmp` 内存挂载。镜像构建上下文只包含代码及依赖清单，不包含本机 data、同步来源、密钥、导出文件和测试证据。

```sh
docker compose stop
```

停止信号会关闭定时工作线程并等待正在处理的请求。Compose 提供两分钟宽限期。若宿主机强制终止或超时杀死进程，重启会将未终结任务标为 interrupted，不将排队记录当作成功。查看任务结果后再决定是否重试。

`docker compose down` 移除容器但保留命名卷。**不要添加 `-v`，它会删除知识数据卷。**更换安装目录可能改变 Compose 项目名与对应卷名，应先确认使用原卷，避免误认为数据丢失。

默认 named volume 不要求手工设置目录权限。若改为宿主目录挂载，需保证 UID 10001 对该目录有读写权限。不要把现有数据目录同时交给两个服务实例运行。

## 升级与恢复

升级前在工作台导出整库备份并验证可以读取备份清单，再保存当前镜像标识：

```sh
docker image inspect albatrosswang/knowledge-capture:0.2.0-alpha.1 --format '{{.Id}}'
```

更新源码后运行 `docker compose up -d --build`。发布前应在独立数据卷验证恢复和兼容性，再替换实际使用实例。镜像回退与数据恢复是两个步骤；数据库发生变更时不能仅凭旧镜像启动成功认定回退完成。

## 网络边界

普通命令行 `serve` 仍只允许回环监听。容器专用入口显式允许内部 `0.0.0.0:8765`，宿主侧仍按 Compose 固定映射至 `127.0.0.1:8765`。原 Host、Origin 和 Bearer 门禁保留。需要修改宿主端口时，使用 `KNOWLEDGE_PUBLIC_PORT=18765 docker compose up -d --build`，然后访问 `http://127.0.0.1:18765`。Compose 同时传入外部端口用于 Host 校验；内部健康检查继续使用 8765。使用直接 docker run 时也须将 `-e KNOWLEDGE_PUBLIC_PORT=18765` 与 `-p 127.0.0.1:18765:8765` 配对。允许的 Host 仍仅 localhost 或回环 IP，改成公网监听不构成受支持的发布方案。远程访问应另行设计认证、TLS 与可信入口，不能取消现有门禁。

容器内 `127.0.0.1` 指向容器自己。连接宿主机模型或 reader 时，Docker Desktop 可使用其宿主网关地址；机房服务需填写容器网络实际可达地址，并单独完成连接及业务样本验证。

## 发布验收

本地构建后至少核对容器健康、未授权 API 返回 401、错误 Host 被拒绝、中文笔记新增与精确历史读取、采集任务终态、重启后数据与令牌保留。包含模型能力的验收另外检查真实输出、来源与引用；镜像构建通过本身不代表这些能力已完成。
